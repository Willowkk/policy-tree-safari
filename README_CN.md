# 国策树 · Safari 单机版

[English](README_EN.md) · [产品设计](../design/v0.1/DESIGN_CN.md)

免登录、本机保存的个人 PWA。国策树和神圣座位记录留在当前浏览器，支持离线使用及 JSON 导出、导入。没有云同步、账号绑定、专注计时或系统提醒。

正式地址：[打开应用](https://willowkk.github.io/policy-tree-safari/)。v0.4 沿用此地址，界面按已确认的 HTML 草稿改造。

## 四个入口

底部顺序为 **今日 · 树形图标 · 设置 · 座椅图标**。树形图标进入 My Tree，座椅图标进入神圣座位。每页不再显示左上角“国策树”品牌标题。

### 今日

- 从右上角“候选库”准备或选择规则，主要填写名称和自由正文；草稿及已退回的记录仍可访问。
- 今天先选一条尝试，做到后点击“我做到了”，明确选择生效父节点或顶层位置，再确认点亮。
- 每个本地数据空间按 **Asia/Shanghai（北京时间）00:00** 换日，每天最多点亮一条；不要求每天点亮。顶层、子节点和重新点亮同样计数。
- 更换尝试、修改内容和准备候选不占额度。当天点亮后又退回，也不返还额度。
- 不显示补库提示，也没有“今天先做好一件事”等口号。

### My Tree

- 真正的父子连线树；宽树可横向浏览。
- 节点只显示名称和数字。数字表示最近一次点亮以来的坚持天数，**当天为 1，次日为 2**，按北京时间日历日计算。
- 点击节点展开详情，再点同一节点收起，点击其他节点切换。
- 详情只展示内容、点亮时间、已坚持、修改记录；不显示创建时间。
- 生效规则可以修改正文，保存修改时间及前后内容；点亮时间、坚持天数和父节点保持不变。
- 记录违反时先确认影响范围，只退回本节点及其生效后代。祖先、兄弟分支和历史保留。调整后可恢复待选、重新尝试，再次点亮从 1 开始。

未打开、未记录或当天没有触发规则，不自动算违反。坚持天数不是每日逐条打卡次数，也不是应用独立验证的行为成绩。

### 神圣座位

这里只手动记录现实中已经发生的结果，**没有倒计时、开始/预约流程或自动判定**。

- 点击“新增”填写名称和规则，可以管理多个座位。
- 卡片默认只显示名称和当前主链成功次数；点击展开规则、记录操作、判例和历史，再次点击收起。
- 选择“主链”或“预约链”后记录完成，相应成功次数加 1；可选填写本次内容。
- “记录情况”可以允许并建立判例，或确认违规。违规只清零该座位当前所选链，另一条链和其他座位不受影响。
- 当前一代已经允许的相同条件不能再判违规。允许情况不自动增加成功次数。断链后历史及旧代判例保留，旧代判例归档，新的链重新从 0 开始。
- 主链记录是否完成，预约链记录是否按约定开始；不用、不发预约信号或隔几天再用不会自动断链。
- 修改座位名称和规则会记录前后内容，不清零链。
- 编辑或记录情况时仍可切换座位；各自未提交的文字及所选链会在本次页面内保留。违规确认不会跨座位继承。未提交草稿不算记录，刷新后保留草稿不属于本版保证。

神圣座位与国策树分别运行；任一侧失败不自动影响另一侧。

### 设置

只有两项常规操作：**导出 JSON、导入 JSON**。必要的保存错误及应用更新提示仍会出现。

## 保存、导出与恢复

每次操作只有在本机写入成功后才显示成功，离线时规则相同。写入失败会提示错误，不应视作完成。

“设置 → 导出 JSON”包含国策、父子关系、点亮/退回历史、规则修改、复盘、全部座位、两条链、判例和座位记录。iPhone 若打开系统分享面板，可选“存储到‘文件’”；若下载文件，请在 Safari 下载列表或“文件”App 找到并妥善保存。取消分享不等于完成备份。

“设置 → 导入 JSON”只接受 JSON 文件，先验证并确认，再安全合并：

| 情况 | 处理 |
| --- | --- |
| 新 ID 的国策、事件或座位 | 加入本机记录 |
| 已有相同 ID | 保留当前本机版本，不覆盖 |
| 合并后关系、同日点亮、链记录不一致 | 整次拒绝，不部分导入 |
| 格式无效、文件过大或写入失败 | 提示错误，保留当前已保存数据 |
| 旧正式版备份没有座位 | 兼容读取，不生成示例座位 |
| 旧云版兼容快照 | 迁移已保存数据，不重放待同步操作、自动确认点亮或迁移提醒 |
| HTML 草稿 `policy-tree-preview` v1 | 严格转换后按正式规则校验、合并，不整体替换 |

导入不是双向同步。电脑修改同一条规则后导回手机，不会覆盖手机已有的同 ID 内容；向空数据空间导入完整备份更适合换机。草稿备份若包含同一天点亮多个节点或不合法记录，会明确拒绝整次导入，不改日期、不删除节点来绕过规则，请保留原文件。导入和导出文件均限制在 20 MiB 以内。

建议集中修改后、换设备前或清除网站数据前各导出一次。备份含私人原文，请存放在信任的位置；应用不会自行把文件上传到 iCloud 等服务。

## 在 iPhone 上使用

1. 联网，用 Safari 打开[正式网址](https://willowkk.github.io/policy-tree-safari/)。
2. 打开“分享 → 添加到主屏幕”；如果出现“作为网页 App 打开”，保持开启，再点“添加”。[Apple 使用说明](https://support.apple.com/zh-cn/guide/iphone/iphea86e5236/ios)
3. 从主屏幕图标打开一次，保持联网，让离线缓存准备好。
4. 缓存可用时可以离线使用核心记录功能。

建议选定一个主要入口长期使用。Safari 标签页和主屏幕 App 可能有不同存储；记录没有出现时，从原入口导出，在新入口导入。安装不是备份，也无需 Apple 开发者会员或每七天续签。

Mac、Windows 可直接用现代浏览器访问；每个设备保存自己的数据，不自动互通。

## 旧版升级与换网址

原网址下的旧正式版本机数据会按兼容格式读取，不因新界面重置。首次读取旧数据不自动写入，下次成功保存才升级本地存储封装。已有创建时间可保留作为兼容字段，但界面不展示；新节点不另外记录创建时间。

本地存储封装升级到版本 2，新客户端读取版本 1 和 2。仍打开着的旧版标签页不能继续修改升级后的数据，需刷新到新版本后再操作；这用于防止旧程序覆盖新增座位记录。业务 JSON 状态仍使用兼容的 `schemaVersion: 1`，与本地封装版本是不同概念。

不同网址使用独立的本机存储。若从旧 ChatGPT 站点迁入，应先用旧浏览器或主屏幕入口导出，再到此网址的新入口导入，确认树和历史完整。旧主屏幕图标仍指向旧网址，需重新添加。

## 本地与离线边界

普通同源标签页可以共享本机数据；不同设备、浏览器、无痕窗口、网址或主屏幕入口不能假定共享。朋友访问同一个网址会使用自己的数据空间，不会看到你的规则。

应用程序由静态服务分发，运行时不发送国策或座位原文。首次访问、离线缓存尚未准备好时需要联网；缓存程序与保存个人数据是两件不同的事。浏览器数据被清除或回收后，需要已导出的 JSON 恢复，服务器没有副本。[WebKit 存储说明](https://webkit.org/blog/14403/updates-to-storage-policy/)

发现新版本时，由用户选择更新时机，先保存表单再刷新。应用更新不应清除记录，更新前仍建议导出备份。

应用不收会员费，也没有付费云同步依赖。静态托管和网络可用性仍取决于服务环境；用户已反馈当前网址可打开，不代表所有地区或网络都有保证。

## 开发与验证

在 `safari/` 中运行：

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

构建包含 TypeScript 检查，静态产物为 `dist/`。默认构建在根路径部署，GitHub Pages 使用：

```sh
POLICY_TREE_BASE=/policy-tree-safari/ npm run build
```

Service Worker 离线行为需在生产构建和 HTTPS 环境验证。不要双击 `dist/index.html` 当作正式安装入口。GitHub Actions 发布沿用原网址。

2026-10-18 本地验证：**79/79 测试通过**，TypeScript 检查与 GitHub 子路径生产构建通过。桌面内置浏览器以 `390 × 844` 视口验证候选、明确挂载、首日计 1、内容修改及节点折叠，多座位草稿和判例切换、两条链独立。实际下载 JSON 后在空白本地入口恢复 5 条国策和 2 个座位；停服后重载、离线新增记录并再次重载均保留，Service Worker 更新也保留旧数据。

这些是本地验证结果，本节不记录线上发布结论。真实 iPhone 主屏幕安装、系统分享及文件恢复尚未实机验证；模拟手机视口不能替代。

当前主实现是本目录，`../web/` 和 `../wechat/` 仅为历史实现。
